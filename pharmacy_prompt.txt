=====================================================================
ПРОМПТ: Full-stack веб-приложение «Аптека» (университетский проект)
=====================================================================

Ты — опытный full-stack разработчик. Создай полностью рабочий проект
веб-сайта аптеки: backend + база данных (файл SQLite) + frontend +
Docker. Проект должен запускаться ОДНОЙ командой без какой-либо
ручной настройки. Пиши чистый, читаемый код с понятной структурой —
проект будет защищаться в университете.

---------------------------------------------------------------------
1. СТЕК
---------------------------------------------------------------------
Backend:
  - Python 3.12
  - FastAPI
  - SQLAlchemy 2.x (ORM)
  - SQLite (файл data/pharmacy.db)
  - Pydantic v2 (схемы запросов/ответов)
  - JWT-аутентификация (python-jose или PyJWT)
  - Хеширование паролей: bcrypt (passlib[bcrypt])
  - Загрузка файлов: python-multipart
  - Экспорт в Excel не требуется (только то, что указано ниже)

Frontend:
  - React 18 + Vite
  - React Router (маршрутизация, SPA)
  - Axios или fetch для запросов к API
  - Состояние: React Context (auth, корзина) — без Redux
  - Стили: простой и аккуратный CSS (CSS Modules или Tailwind),
    адаптивная вёрстка (desktop + mobile)
  - Корзина хранится в localStorage

Инфраструктура:
  - Docker (multi-stage Dockerfile)
  - docker-compose
  - ОДИН контейнер, ОДИН порт (8000): FastAPI раздаёт и API, и
    собранную статику React

---------------------------------------------------------------------
2. ОБЩИЕ ПРАВИЛА АРХИТЕКТУРЫ
---------------------------------------------------------------------
  - Все эндпоинты backend — под префиксом /api
    (/api/auth, /api/medicines, /api/categories, /api/orders, ...).
  - Все остальные пути (не /api, не /docs, не /uploads, не /assets)
    отдают index.html — чтобы обновление страницы на
    /admin/orders и др. не давало 404 (SPA fallback).
  - Swagger доступен по /docs.
  - Загруженные картинки хранятся в data/uploads/ и раздаются по
    /uploads/<имя_файла>.
  - При старте приложения:
      * если файла БД нет — автоматически создаются все таблицы;
      * если БД пустая — автоматически выполняется seed (тестовые
        данные, см. раздел 7).
  - Конфигурация через переменные окружения (.env), у всех
    переменных есть значения по умолчанию — проект запускается
    даже без .env.
  - Валидация входных данных через Pydantic, понятные сообщения
    об ошибках (HTTP 400/401/403/404/409).
  - Разделение backend на слои: models, schemas, routers,
    services (бизнес-логика), core (config, security, db).

3. БАЗА ДАННЫХ (SQLite) — ТАБЛИЦЫ
---------------------------------------------------------------------
users
  id, email (unique), password_hash, full_name, phone,
  role ('user' | 'admin'), created_at

categories
  id, name (unique), description, created_at

medicines
  id, name, description, category_id (FK), manufacturer,
  form (таблетки / капсулы / сироп / мазь / капли / раствор / ...),
  dosage (напр. "500 мг"), price, stock (остаток, int),
  expiry_date (срок годности), requires_prescription (bool),
  image_url, created_at, updated_at

orders
  id, user_id (FK), status, delivery_method ('pickup' | 'delivery'),
  delivery_address (nullable, обязателен при delivery),
  comment, total_price, created_at, updated_at

order_items
  id, order_id (FK), medicine_id (FK), quantity,
  price_at_purchase (цена на момент заказа)

favorites
  id, user_id (FK), medicine_id (FK), created_at
  UNIQUE(user_id, medicine_id)

reviews
  id, user_id (FK), medicine_id (FK), rating (1..5), text,
  created_at
  UNIQUE(user_id, medicine_id) — один отзыв на лекарство от
  пользователя

4. ФУНКЦИОНАЛ — ПОЛЬЗОВАТЕЛЬ (role = user)
---------------------------------------------------------------------
4.1 Регистрация и вход
  - Регистрация (email, пароль, ФИО, телефон).
  - Вход → JWT-токен. Токен хранится на фронте, отправляется в
    заголовке Authorization: Bearer.
  - Выход.
  - Каталог и страницы лекарств доступны без авторизации;
    корзина-оформление, избранное, отзывы, личный кабинет —
    только после входа.

4.2 Каталог лекарств
  - Карточки: картинка, название, категория, форма, дозировка,
    цена, наличие, бейдж «По рецепту», средний рейтинг (звёзды).
  - Поиск по названию (частичное совпадение, без учёта регистра).
  - Фильтры: категория, цена от/до, «только в наличии».
  - Сортировка: по цене (возр./убыв.), по названию, по рейтингу.
  - Пагинация.
  - Фильтры и поиск отражаются в URL (query-параметры).

4.3 Страница лекарства
  - Полная информация: описание, производитель, форма выпуска,
    дозировка, срок годности, остаток / «нет в наличии», цена,
    флаг «по рецепту» с предупреждением
    («Препарат отпускается по рецепту врача»).
  - Кнопки: «В корзину» (с выбором количества, не больше остатка),
    «В избранное» (сердечко, toggle).
  - Блок отзывов: средняя оценка, количество отзывов, список
    отзывов (имя, звёзды, текст, дата).
  - Форма отзыва (1–5 звёзд + текст) для авторизованного
    пользователя; пользователь может отредактировать/удалить
    свой отзыв.

4.4 Избранное
  - Добавление/удаление из избранного (из каталога и со страницы
    лекарства).
  - Отдельная страница «Избранное».

4.5 Корзина
  - Список товаров, изменение количества, удаление, итоговая сумма.
  - Нельзя положить больше, чем есть в наличии.

4.6 Оформление заказа
  - Способ получения: «Самовывоз» или «Доставка».
    При «Доставке» поле адреса обязательно.
  - Комментарий к заказу (необязательно).
  - Backend при создании заказа:
      * проверяет наличие каждого товара (stock >= quantity),
        иначе ошибка 409 с понятным сообщением;
      * фиксирует price_at_purchase;
      * считает total_price на сервере (не доверять фронту);
      * создаёт заказ со статусом new.
  - После оформления — корзина очищается, редирект на страницу
    заказа / личный кабинет.

4.7 Личный кабинет
  - Профиль (ФИО, телефон, email).
  - История заказов: номер, дата, состав, сумма, способ получения,
    статус (цветной бейдж).
  - Детали заказа.
  - Отмена заказа пользователем — только пока статус new.

---------------------------------------------------------------------
5. ФУНКЦИОНАЛ — АДМИН (role = admin)
---------------------------------------------------------------------
Отдельный раздел /admin с боковым меню, доступен только админу
(проверка роли и на фронте, и на backend — 403 для не-админов).

5.1 Дашборд
  - Количество новых заказов (status = new).
  - Выручка (сумма completed-заказов): всего и за последние 30 дней.
  - Всего заказов, всего лекарств, всего пользователей.
  - Топ-5 продаваемых лекарств (по количеству в completed-заказах).
  - Список «Заканчиваются»: лекарства с остатком < 5.
  - Список «Истекает срок годности» (см. 5.5).

5.2 CRUD категорий
  - Список, создание, редактирование, удаление.
  - Нельзя удалить категорию, в которой есть лекарства
    (ошибка 409 с сообщением).

5.3 CRUD лекарств
  - Таблица с поиском и фильтром по категории.
  - Создание / редактирование: все поля из таблицы medicines.
  - Загрузка картинки (jpg/png/webp, ограничение размера ~5 МБ).
  - Удаление.
  - Быстрое изменение остатка.

5.4 Управление заказами
  - Список заказов с фильтром по статусу, сортировка по дате
    (новые сверху), новые заказы визуально выделены.
  - Автообновление списка каждые 10 секунд (polling,
    без WebSocket) + счётчик новых заказов в меню.
  - Детали заказа: покупатель (ФИО, телефон, email), состав,
    сумма, способ получения, адрес, комментарий.
  - Смена статуса кнопками.

5.5 Подсветка срока годности
  - В таблице лекарств и на дашборде:
      * срок истёк — красная подсветка + бейдж «Просрочено»;
      * истекает в течение 30 дней — оранжевая/жёлтая подсветка
        + бейдж «Истекает»;
  - Порог (30 дней) вынести в конфиг (EXPIRY_WARNING_DAYS).
  - Просроченные лекарства нельзя заказать (не показываются
    как доступные в каталоге или помечены «Недоступно»).

5.6 Модерация отзывов
  - Админ может просматривать и удалять отзывы.

6. ЖИЗНЕННЫЙ ЦИКЛ ЗАКАЗА (бизнес-логика — важно!)
---------------------------------------------------------------------
Статусы:
  new        — создан пользователем, ждёт обработки
  accepted   — принят админом
  ready      — собран, готов к выдаче / отправке
  completed  — выдан / доставлен
  cancelled  — отменён

Разрешённые переходы:
  new       → accepted   (админ)
  new       → cancelled  (админ или пользователь)
  accepted  → ready      (админ)
  accepted  → cancelled  (админ)
  ready     → completed  (админ)
  ready     → cancelled  (админ)
Любые другие переходы — ошибка 400.

Работа со складом:
  - При переходе new → accepted остаток (stock) каждого
    лекарства уменьшается на количество в заказе. Если на момент
    принятия товара уже не хватает — ошибка 409, статус не
    меняется.
  - При отмене заказа, который уже был accepted или ready,
    товар возвращается на склад (stock увеличивается).
  - При отмене заказа в статусе new склад не меняется.
  - Все изменения склада и статуса — в одной транзакции.

Всю логику переходов вынести в отдельный сервис
(services/order_service.py).

10. DOCKER
---------------------------------------------------------------------
Dockerfile (в корне, multi-stage):

  # Этап 1: сборка React
  FROM node:20-alpine AS frontend
  WORKDIR /front
  COPY frontend/package*.json ./
  RUN npm ci
  COPY frontend/ .
  RUN npm run build

  # Этап 2: FastAPI + статика
  FROM python:3.12-slim
  WORKDIR /app
  ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
  COPY backend/requirements.txt .
  RUN pip install --no-cache-dir -r requirements.txt
  COPY backend/ .
  COPY --from=frontend /front/dist ./static
  EXPOSE 8000
  CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]

docker-compose.yml:

  services:
    app:
      build: .
      container_name: pharmacy
      ports:
        - "8000:8000"
      volumes:
        - ./data:/app/data
      env_file:
        - path: .env
          required: false
      restart: unless-stopped
      healthcheck:
        test: ["CMD", "python", "-c",
               "import urllib.request; urllib.request.urlopen('http://localhost:8000/api/health')"]
        interval: 30s
        timeout: 5s
        retries: 3

.dockerignore: node_modules, dist, __pycache__, *.pyc, .venv,
  data/*.db, data/uploads, .git, .env

.env.example:
  SECRET_KEY=change-me-in-production
  ACCESS_TOKEN_EXPIRE_MINUTES=1440
  DATABASE_URL=sqlite:///./data/pharmacy.db
  UPLOAD_DIR=./data/uploads
  EXPIRY_WARNING_DAYS=30
  LOW_STOCK_THRESHOLD=5
  ADMIN_EMAIL=admin@pharmacy.local
  ADMIN_PASSWORD=admin123

.gitignore: node_modules, dist, __pycache__, .venv, .env,
  data/*.db, data/uploads/

Требование: запуск проекта = `docker compose up --build`,
ничего больше. На хосте нужен только Docker (Node.js и Python
не нужны).

15.1 Изменения в БД
  medicines — новые поля:
    discount_percent  int, 0..90, по умолчанию 0
    is_deal_of_day    bool, по умолчанию false («Выгодно сегодня»)
  Итоговая цена (final_price) = round(price * (100 - discount_percent) / 100, 2).
  Считается на backend и отдаётся в API вместе с price и
  discount_percent (фронт её не вычисляет).

  promotions (новая таблица) — баннеры акций:
    id, title, description,
    discount_percent (nullable, информационно),
    category_id (FK, nullable — ссылка «Выбрать» ведёт в каталог
                 с этой категорией),
    starts_at (date), ends_at (date, nullable = «Постоянно»),
    theme ('teal' | 'amber' | 'blue' — цвет баннера),
    is_active (bool), created_at

15.2 Бизнес-логика
  - При создании заказа price_at_purchase = final_price (со скидкой);
    total_price считается на сервере по final_price.
  - Фильтр цены от/до и сортировка по цене в каталоге работают по
    final_price.
  - Хиты продаж: топ-8 лекарств по сумме quantity в заказах со
    статусом completed; если продаж мало — добираются по рейтингу.
    Просроченные и с stock = 0 не показываются.
  - Товары дня: is_deal_of_day = true, в наличии, не просрочены.
    Таймер на фронте считает время до полуночи (чисто визуально).
  - Активные акции: is_active = true и starts_at <= сегодня и
    (ends_at is null или ends_at >= сегодня).

15.3 API (дополнительно)
  GET    /api/promotions                 активные акции (публично)
  GET    /api/admin/promotions           все акции (admin)
  POST   /api/admin/promotions           (admin)
  PUT    /api/admin/promotions/{id}      (admin)
  DELETE /api/admin/promotions/{id}      (admin)
  GET    /api/medicines/deals            товары дня
  GET    /api/medicines/bestsellers?limit=8
  GET    /api/medicines?...&on_sale=true  только со скидкой
  В POST/PUT /api/medicines — поля discount_percent, is_deal_of_day.

15.4 Админка
  - Новый пункт меню «Акции»: таблица + создание/редактирование/
    удаление (с подтверждением), переключатель активности.
  - В форме лекарства: «Скидка, %» и чекбокс «Товар дня».
  - В таблице лекарств: колонка скидки, бейдж «Товар дня».

15.5 Frontend
  - Цена в карточке/строке: если есть скидка — новая цена красным,
    старая зачёркнутой, бейдж «−N%».
  - В каталоге: фильтр-переключатель «Со скидкой» и ссылка «Акции»
    в шапке (ведёт на каталог с on_sale=true + баннеры акций сверху).

15.6 Seed (дополнительно)
  - 3 акции: «Сезон простуды −20%» (teal, категория «Простуда и
    грипп»), «Витамины: 2 упаковки по цене одной» (amber, категория
    «Витамины»), «Бесплатная доставка от 200 смн» (blue, без даты
    окончания).
  - Скидки у 6–8 лекарств (10–30%), из них 4 — товары дня.
  - Чтобы «Хиты продаж» были не пустыми — completed-заказы в seed
    содержат несколько разных лекарств.

      доставка и самовывоз; отзывы; FAQ; призыв к регистрации;
      подвал.
  design/catalog-user.html   — каталог для вошедшего пользователя
      («/» после входа и «/catalog»): левая колонка с категориями,
      фильтрами и «Вы уже покупали»; приветствие с текущим заказом
      и его статусом; список препаратов строками (остаток полоской,
      бейджи, избранное, счётчик количества); корзина справа
      с выбором способа получения.
  Гость, открывший /catalog, видит тот же каталог, но без
  приветствия и без «Вы уже покупали»; корзина у гостя предлагает
  войти для оформления.

  Токены: шрифт Golos Text (Google Fonts, в Docker — локально через
  @fontsource/golos-text, чтобы работать без интернета);
  цвета: ink #0F2A33, muted #607780, line #E1EAEC, rail #F4F8F9,
  бирюзовый #00A19A (мягкий #E0F5F3), рецепт/скидка #C0392B,
  «истекает» #C27C0E. На мобильных колонки складываются в одну,
  корзина открывается отдельной страницей.

=====================================================================
17. ВАЛЮТА И ЛОКАЛИЗАЦИЯ
=====================================================================
  - Все цены — в таджикских сомони (TJS). В интерфейсе формат
    «56 смн», дробная часть с запятой и только если она не нулевая:
    «16,50 смн». Разделитель тысяч — пробел: «1 250 смн».
  - Форматирование — одна функция formatPrice() во frontend
    (src/utils/format.js), нигде не писать валюту вручную.
  - В БД цены хранятся как Numeric(10, 2), без валюты.
  - Город — Душанбе (тексты доставки, адрес аптеки, телефон в
    формате +992). В seed адреса доставки — улицы Душанбе.
  - Порог бесплатной доставки и стоимость доставки на макете
    (200 смн / 15 смн) — только текст на странице, в расчёт заказа
    не входят.
